# Pre-registered analysis plan: confirmatory corpora (seed 7)

Committed to git **before any confirmatory data existed**; the commit that adds
this file is the reference. Everything below is fixed: data, labels, detectors,
comparisons, statistics, and the wording each outcome licenses. Any deviation
is reported as a deviation, with its reason, next to the result.

## Why a confirmatory run

All method development (e0-e10), the 2026-10-20 blind review, and every number
in the draft used the development corpora `data/trajectories/healthcare_v2/
{70B,8B}_42.jsonl` (protocol `v2`). The review found three things that require
fresh data rather than reanalysis:
1. **Feedback display bug (v2).** The agent was shown sign(tanh(F logit p)):
   no reaction appeared as "+", and below p = 0.5 accept/contradict appeared
   inverted (9% of 70B and 53% of 8B observed signals). Detectors always read
   the true signals; the agent's in-context feedback did not match the paper.
2. **Resamples only on 5 attributes.** Sampling baselines could not see most
   commitments behind the composite label.
3. **The composite label is mostly not user-specific.** On 70B, 798 of 1,136
   confident errors are on attributes fully determined by the intake answers;
   a context-only classifier (no feedback) scores 0.772 vs the posterior's
   0.775 on it.

Protocol `v2fb` for the five healthcare corpora: identical sessions/schedules/
truth/eps = 0.25 symmetric flip/no-feedback attributes as v2, seed 7 (sessions
never used in development), the agent sees the raw reaction "+"/"-"/"none",
and **every turn** gets k = 3 resamples at T = 0.9 from the exact context of its
own guess. The routed agent re-prompts once on unparseable or out-of-set values
(the v2 agent accepted out-of-set values); parse statuses are in
`meta.parse_status`. Exclusions: none by outcome. A model whose run aborts on
the parse-failure guard (>25% failed turns) is reported as not following the
protocol, without detection numbers. A corpus that completes < 300 sessions is
reported but excluded from pooled estimates.

## Labels (both evaluated on noise-free truth; never detector-visible)

- **L_U (primary, user-specific)** `pge.benchmarks.healthcare_v2.eval_label_user`:
  the eval_label_v2 rule (>= half of the confident, p >= 0.6, commitments
  wrong) restricted to commitments whose true value is **not determined by that
  session's intake answers** (`user_dependent_attrs`: varies over the hidden
  profile's support). 0 if there are none. Base rates on the dev corpora
  (computed from labels only, before any detector was evaluated on L_U):
  70B 0.413, 8B 0.275.
- **L (secondary, composite)** `eval_label_v2`, as in development.

## Splits and statistics

`split_task_ids(ids, 0.7, s)`, s in {42, 123, 456}; fit on train, score test
once; per-corpus AUROC = mean over the three split seeds. Differences: paired
bootstrap, 2000 resamples, **clustered by session** (a session appearing in
several seeds' test sets is resampled as one unit); a difference is called
significant iff its 95% CI excludes 0. Pooled over the five healthcare agents:
the mean of per-agent differences, CI by stratified cluster bootstrap
(sessions resampled within each agent). No multiplicity correction; every
comparison listed here is reported whatever its outcome.

## Detectors (frozen at this commit)

- **Primary: V6** `ChannelPosterior()`; for L_U, `ChannelPosterior(event_attrs=
  USER_DEPENDENT_SCHEMA)` trained on L_U train labels.
- Secondary: V3 `IndependentPosterior(by_value=True)`, same event handling.
- Ablation: `PriorOnly(V6)`, `PriorOnly(V3)`: same fitted priors, the test
  user's reactions ignored. **Feedback increment = V6 - PriorOnly(V6).**
- Supervised context baselines (`pge/baselines/context_lr.py`): `ctx_lr`
  (commitment cells + |H| + #turns + mean confidence; no feedback, no samples)
  and `ctx_lr+fb` (plus per-cell feedback counts). C = 0.1, fixed.
- Sampling: SelfCheckGPT and semantic entropy (k = 3). For L they use all
  turns; for L_U, turns on schema user-dependent attributes only (the
  commitments the label is about). k = 10 SelfCheckGPT on the 70B split-seed-42
  test sessions if the optional step 5b runs.
- Feedback heuristics and structure, as in e6: highconf_contradicted,
  neg_signal_fraction, dag_logreg, GCN, best graphon; mean confidence oriented
  on train.
- CoVe (70B self-verification, T = 0), 70B corpus only.

## Hypotheses and the claim each outcome licenses

Primary, on **L_U**, pooled over agents (per-agent results always reported):

| id | comparison | claim if CI excludes 0 (in the stated direction) | claim otherwise |
|---|---|---|---|
| H1 | SelfCheckGPT, SE AUROC | "sampling detectors are near chance on user-specific hallucination" iff the pooled 95% CI lies within [0.40, 0.60] | report the AUROC; drop "near chance" |
| H2 | V6 - PriorOnly(V6) > 0 | "the user's implicit reactions add detectable signal beyond population base rates" | "at eps = 0.25 with partial feedback, reactions add no detectable signal beyond base rates" |
| H3 | V6 - ctx_lr > 0 | "PGE beats the strongest context-only detector" | "context alone matches PGE on this label" |
| H4 | V6 - SelfCheckGPT > 0, V6 - SE > 0 | "PGE beats sampling-consistency detectors" | as measured |

Secondary: the same comparisons on L; V6 vs ctx_lr+fb on both labels (no
directional prediction; reported as is); CoVe on 70B; per-agent results.

LLM-simulated patient: audit (P(-1|wrong), P(-1|right), lift, by persona and
attribute); V6, PriorOnly(V6), ctx_lr, ctx_lr+fb, highconf_contradicted on L_U
and L, profile arm primary.

Closed-loop clarification (70B, split-seed-42 test sessions, V6 picks):
**primary outcome = wrong confident user-dependent commitments per session**;
secondary: L_U rate, L rate, wrong confident commitments. Comparisons:
posterior@1 vs no_question@1, random@1, lowconf@1; posterior@2 vs
detailed_questions and vs rerun_full; detailed_questions vs rerun_full.
"Choosing by posterior risk beats choosing at random" iff posterior@1 -
random@1 < 0 with CI excluding 0 on the primary outcome; questions per session
are reported for every condition.

## What stays from development

Development results (dev corpora, protocol v2) stay in the paper only where
they are labelled as development evidence: the dissociation analysis, channel
robustness (e7), the noise sweep, the ablation. Headline tables come from the
confirmatory corpora. The analysis script (`eval/e11_confirmatory.py`) is
written to implement this file exactly and is committed before the
confirmatory data are pushed to the repository.

## Amendment 1 (committed 2026-10-20, before any confirmatory data was pushed or seen by the analysts)

Motivation: running this plan's analysis (`eval/e11_confirmatory.py --dev`) on
the DEVELOPMENT corpora showed that on L_U the supervised `ctx_lr+fb` exceeds
V6 on 70B (0.813 vs 0.678; 420 labelled training sessions), while V6 leads on
8B (0.722 vs 0.630; 140 training sessions). The original hypotheses H1-H4 and
their wording rules are unchanged. Added, all secondary:

| id | comparison (L_U, pooled) | claim if CI excludes 0 | claim otherwise |
|---|---|---|---|
| H2b | ctx_lr+fb - ctx_lr > 0 | "the user's reactions add detectable signal beyond the commitments themselves (supervised detector)" | "no detectable feedback increment for the supervised detector" |
| H4b | ctx_lr+fb - SelfCheckGPT > 0, ctx_lr+fb - SE > 0 | "detectors on PGE observables beat sampling-consistency detectors" | as measured |

Data efficiency (descriptive, no test): test AUROC of V6, ctx_lr and
ctx_lr+fb when trained on 25, 50, 100, 200 and all train sessions of each
split seed (5 random subsets per size, both classes required; test split
unchanged), on both labels, for every corpus with >= 300 sessions.

Terminology for the paper: "PGE" names the protocol (explicit commitments +
implicit reactions); V6 is the protocol's label-event posterior; ctx_lr and
ctx_lr+fb are generic supervised detectors on the same observables. Claims
about "PGE beats X" in H3/H4 refer to V6, as originally registered.
